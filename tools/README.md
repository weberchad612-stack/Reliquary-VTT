# tools

Scripts Claude runs in its workspace. Requirements: Node.js 20 or newer (`npm install` once in the repo root), and Python 3 with Pillow for the image tools.

| Tool | What it does |
|---|---|
| `bundle.mjs` | Bundles the engine modules into one script for single-file pages, and inlines data (a map folder, JSON, images). `node tools/bundle.mjs <template.html> <out.html> [--data NAME=FILE ...]`. Stamps the board with its build (`/*@BUILD@*/`: version from the build time, commit, uncommitted changes). Used for the board and `examples/demo/`. |
| `mapimport/build.py` | The map importer: turns a map image in a PDF you own into map, wall, terrain and lighting data for a private pack. `python3 tools/mapimport/build.py <map-folder>/import.json`. The settings file names the PDF and page and holds every correction (see the header of `build.py`). Steps: `extract.py` (image from the PDF), `grid.py` (automatic grid calibration), `mask.py` (wall, door and window pixels), `features.py` (doors, windows, proposed arrow slits; each door becomes one segment per leaf, with double doors paired and a hinge and swing side chosen; each detected door's opening is then cleared through the wall so its outline does not pinch the doorway), `vectorize.py` (wall outlines to segments), `lighting.py` (lighting regions and lights from the settings' `lighting` block: the outdoors by sealed flood, roofless areas from the terrain, colour and intensity; warns about a light with bright light but no dim radius; writes `lighting.json`), `terrain.py` (terrain areas from the settings' `terrain` block: rooms, rectangles, polygons and colour classes, split by keyed room; writes `terrain.json`). Needs Python 3 with `tools/mapimport/requirements.txt` and poppler's `pdfimages`. |
| `mapimport/strip_numbers.py` | Removes printed location numbers from an area map's image: finds each marker near its pin (bare outlined digits, or a disc), masks it with its outline and fills it by inpainting. `python3 tools/mapimport/strip_numbers.py <map-folder> [--only 14,17] [--scale S]`. Writes a stripped copy, the mask (for a generative fill tool) and a check sheet; never changes the original. Good on flat ground, smudgy over busy detail: see `docs/best-practices/map-importer.md` section 5b. |
| `samples/sample_keep.py` | Generates the Sample Keep, the original 48 x 48 test map in `examples/sample-pack` (walls, terrain, lighting with coloured lights and red, green and blue test lights in the armoury, image) and its demo setup `examples/demo/keep-setup.json`. Edit the generator, not the generated files. |
| `samples/sample_village.py` | Generates the Sample Village, an original area map (a small town) in `examples/sample-pack`: the picture and `map.json` with public places, a GM-only place and a wide edge pin. |
| `validate.mjs` | Checks a pack's maps and walls, and optionally a save's map state, against the schemas and the design rules. `node tools/validate.mjs <pack-dir or map-dir> [--save <save-dir>]` (also `npm run validate -- ...`). Checks terrain files and a save's temporary terrain and `terrain_on`/`terrain_off` lists, and lighting: presets, colours and intensities, and a save's light and region changes. Also warns when walls pinch a doorway (less of an open door is clear than it should be). Exit code 1 on errors. |
| `sight.mjs` | Asks the sight engine what is visible. `node tools/sight.mjs <map-dir> --from X,Y [--to X,Y] [--state FILE] [--range FEET]` (range unlimited by default, to the map's edge). Points are in cells (3.5,4.5 is the centre of cell 3,4). Prints the visibility polygon, or `{"visible": true/false}` with `--to`. `--token X,Y,SIZE` gives what a whole token sees (one polygon per viewpoint). |
| `campaign.mjs` | Campaigns on disk to the board's database records and back. `records`/`seed <pack> <save>` (the campaign as records; `seed` inlines images for a memory board), `save <records> <save-dir>` (writes the save, backing up the previous one, last 5 kept), `check <pack> <save>` (round trip), `ops-load <pack> <save> --assets ASSETS.json` (db_write batches, images reused by SHA-256, `board/meta` last), `ops-clear <listing.json>` (versioned deletes), `verify <records> <pack> <save>` (save on disk vs the board). Procedure: [best practices: the board](../docs/best-practices/board.md). |
| `area.mjs` | Area templates. `node tools/area.mjs <map-dir> --shape burst\|cone\|line\|emanation --ft N [--caster ID\|X,Y[,SIZE]] [--at X,Y] [--dir NAME] [--angle DEG] [--toward X,Y] [--state FILE] [--by gm\|player] [--no-walls]`. Prints the squares covered and reached past walls, who is in the area (tokens from `--state`), and the `templates/<id>` record to write to the board. |
| `effect.mjs` | Effect badges. `node tools/effect.mjs <token.json> (add <condition> [VALUE] \| custom "<name>" [--kind good\|bad\|neutral] \| remove <id or name> \| clear \| dead \| alive \| elevation <FEET>) [--detail T] [--until T] [--source T] [--gm-only]`; `node tools/effect.mjs list` shows the system's conditions. Reads a token record, checks against the system's conditions, prints the changed token to write back. |
| `note.mjs` | Map notes from chat. `node tools/note.mjs <map-dir> --at X,Y --text "TEXT" [--gm-only] [--by claude\|gm\|player] [--id ID]`. Checks the point is on the map and the text fits (500 characters); prints the `notes/<id>` record to write to the board. |
| `move.mjs` | Asks the movement engine. `node tools/move.mjs <map-dir> --token X,Y[,SIZE] (--to X,Y \| --step DX,DY \| --reach FEET) [--state FILE] [--diagonal 1,2] [--squeeze SIZE]`. Prints the cheapest path and its cost, whether one step is allowed, or every reachable position. |
| `fog.mjs` | Runs the fog of war for a map state: what the PCs see now, which tokens players may see, and the merged explored area. `node tools/fog.mjs <map-dir> --state FILE [--token ID:KIND:X,Y[,SIZE] ...] [--out FILE] [--range FEET]` (range unlimited by default). With `--out`, writes the updated map state. |
| `wall_overlay.py` | Draws a map's wall segments for review, colour-coded by type with one-way arrows. `python3 tools/wall_overlay.py <map-dir> [--out file] [--blank] [--sight X,Y ...] [--state FILE]`. `--blank` draws on a plain grid instead of the map image; `--sight` shades what is visible from each point and `--token X,Y,SIZE` what a token sees, both through `sight.mjs`. `--path X,Y,SIZE:GX,GY` draws a route and `--reach X,Y,SIZE:FEET` shades reachable positions, through `move.mjs`. `--fog player\|gm` paints the fog of war for a state's tokens, through `fog.mjs`. |

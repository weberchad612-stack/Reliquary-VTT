# tools

Scripts Claude runs in its workspace. Requirements: Node.js 20 or newer (`npm install` once in the repo root), and Python 3 with Pillow for the image tools.

| Tool | What it does |
|---|---|
| `bundle.mjs` | Bundles the engine modules into one script for single-file pages, and inlines data (a map folder, JSON, images). `node tools/bundle.mjs <template.html> <out.html> [--data NAME=FILE ...]`. Stamps the board with its build (`/*@BUILD@*/`: version from the build time, commit, uncommitted changes). Used for the board and `examples/demo/`; the published board is built with `--data glossaries=FILE` (`campaign.mjs glossaries`). |
| `mapimport/build.py` | The map importer: turns a map image in a PDF you own into map, wall, terrain and lighting data for a private pack. `python3 tools/mapimport/build.py <map-folder>/import.json`. The settings file names the PDF and page and holds every correction (see the header of `build.py`). Steps: `extract.py` (image from the PDF), `grid.py` (automatic grid calibration), `mask.py` (wall, door and window pixels), `features.py` (doors, windows, proposed arrow slits; each door becomes one segment per leaf, with double doors paired and a hinge and swing side chosen; each detected door's opening is then cleared through the wall so its outline does not pinch the doorway), `vectorize.py` (wall outlines to segments), `lighting.py` (lighting regions and lights from the settings' `lighting` block: the outdoors by sealed flood, roofless areas from the terrain, colour and intensity; warns about a light with bright light but no dim radius; writes `lighting.json`), `terrain.py` (terrain areas from the settings' `terrain` block: rooms, rectangles, polygons and colour classes, split by keyed room; writes `terrain.json`). Print-quality maps: `source.crop_px` cuts one map out of a sheet holding several, `source.scale` resizes, and detection runs on a smaller copy (`detect_cell_px`, default 50) while the board keeps the full image. `features.door_reach_cells` for doors drawn on the wall line; `doors[].drop` removes a false door; `map.start` and `map.links` are copied into `map.json`. `"profile"` merges a saved set of settings for an art style (`profiles.json`). `lines.py`: grid-line suppression, straight walls (proposed automatically or listed by hand, measured to their centre line and thickness, written as thick segments), squaring traced walls, and welding nearly-meeting ends on the 1/32 snap; `interior_erase` clears each keyed room's floor from the mask (docs/best-practices/map-importer.md section 4b). Slow steps are cached (`cache.py`; `--no-cache`), `--room <key>` rebuilds one room's walls, and the report lists wall suggestions (section 4c). Needs Python 3 with `tools/mapimport/requirements.txt` and poppler's `pdfimages`. |
| `mapcheck.mjs` | The map check: sight from every keyed room (`rooms.json`) with every door closed, and the walking routes in the map's `import.json` `checks.routes` with every door open; `checks.sees` lists the views the text allows. `node tools/mapcheck.mjs <map-dir> [--json] [--thorough]`. It also walks every door from both sides, reaches every room from the starting area, and says what each leak went through (`checks.door_walk`, `checks.unreached` explain exceptions). |
| `advimport/` | The adventure importer (docs/best-practices/adventure-importer.md): `roomcrops.py` registers an adventure's per-room map crops to the level maps (room labels, room captions, the book's pawn markers as start squares, their portraits; `--refresh` re-reads captions); `pdfart.py` pulls candidate art out of a PDF with the words printed by each picture, composited onto an opaque ground; `tokenart.py` makes each creature's round token image and full portrait from `art/art.json` and draws a check sheet; `campaign.mjs` builds a campaign save from the pack's `adventure.json` (creatures with their stat blocks, art and the book's differences; object tokens with their contents; ambient sounds, map music, the map's starting state and ledger entries from the book); `roomtable.py` writes each map's room table (`rooms.json`: every keyed area as its squares, by flood fill from a point inside, clipped where a room is open to its neighbours; `--from-crops` proposes the points and titles from `roomcrops.json`, `--overrides` corrects them); `statmatch.mjs` matches each stat block the book prints with the open content and lists what the book changes (weak, elite, HP, Speeds), reading the blocks with the game system's `rulesets/<system>/bookimport.js`; `landing.py` makes the landing page (kind "landing": the book's cover, from a PDF page, one image on it or a file the user gives) and puts it first in `pack.json`; `review.py` writes the private review page (maps with walls, room keys, start squares and objects; the room table, cast, objects, art, illustrations, sound, ledger, notes, decisions and the validator's report).; `run.mjs` runs a pack's whole import from its `pipeline.json` with a status table (out of date, failed, waiting for review); `pagetext.mjs` writes every page as text; `areas.mjs` is the area checklist (every keyed area's checks, doors, light, terrain, treasure and stat blocks against the pack, with proposals); `lootmatch.mjs` checks loot and hazards against the content and the book; `links.mjs` finds stairs and lifts between levels in the text; `cropcheck.mjs` compares rooms with the book's crops; `reviewsheet.py` draws each map's rooms beside the book's crops with walls, suggestions and changes; `sync.mjs` sends the private pack to the user's PC, never over the user's edits; `campaign.mjs --update` refreshes a campaign from its pack and keeps play (docs/best-practices/adventure-importer.md sections 2, 7 and 8). |
| `mapimport/strip_numbers.py` | Removes printed location numbers from an area map's image: finds each marker near its pin (bare outlined digits, or a disc), masks it with its outline and fills it by inpainting. `python3 tools/mapimport/strip_numbers.py <map-folder> [--only 14,17] [--scale S]`. Writes a stripped copy, the mask (for a generative fill tool) and a check sheet; never changes the original. Good on flat ground, smudgy over busy detail: see `docs/best-practices/map-importer.md` section 5b. |
| `samples/sample_keep.py` | Generates the Sample Keep, the original 48 x 48 test map in `examples/sample-pack` (walls, terrain, lighting with coloured lights and red, green and blue test lights in the armoury, image) and its demo setup `examples/demo/keep-setup.json`. Edit the generator, not the generated files. |
| `samples/sample_village.py` | Generates the Sample Village, an original area map (a small town) in `examples/sample-pack`: the picture and `map.json` with public places, a GM-only place and a wide edge pin. |
| `validate.mjs` | Checks a pack's maps and walls, and optionally a save's map state, against the schemas and the design rules. `node tools/validate.mjs <pack-dir or map-dir> [--save <save-dir>]` (also `npm run validate -- ...`). Checks terrain files and a save's temporary terrain and `terrain_on`/`terrain_off` lists, and lighting: presets, colours and intensities, and a save's light and region changes. Also warns when walls pinch a doorway (less of an open door is clear than it should be), checks a pack's visual effects (`effects.json`) and game content (`content/`), and a save's creatures (`actors/`, `actorstate/`: schemas, references into the content, rule elements, each prepared by the rules). `node tools/validate.mjs --content content/pf2e` checks the open content (schemas, an ORC or OGL licence on every document). Exit code 1 on errors. |
| `sight.mjs` | Asks the sight engine what is visible. `node tools/sight.mjs <map-dir> --from X,Y [--to X,Y] [--state FILE] [--range FEET]` (range unlimited by default, to the map's edge). Points are in cells (3.5,4.5 is the centre of cell 3,4). Prints the visibility polygon, or `{"visible": true/false}` with `--to`. `--token X,Y,SIZE` gives what a whole token sees (one polygon per viewpoint). |
| `campaign.mjs` | Campaigns on disk to the board's database records and back. `records`/`seed <pack> <save>` (the campaign as records; `seed` inlines images for a memory board), `save <records> <save-dir>` (writes the save, backing up the previous one, last 5 kept), `check <pack> <save>` (round trip), `ops-load <pack> <save> --assets ASSETS.json` (db_write batches, images reused by SHA-256, `board/meta` last), `ops-clear <listing.json>` (versioned deletes), `verify <records> <pack> <save>` (save on disk vs the board), `tidy <records>` (deletes for content nothing uses and replays the save no longer keeps, after a save), `glossary <ruleset>` (the trait glossary record; saves include the chat, audit log, dice, replays, the ledger and the party's stash and purse: `chat.json`, `audit.json`, `dice.json`, `replays.json`, `ledger.json`, `loot.json`) and `glossaries` (every system's, keyed by ruleset id, to build into the board). Procedure: [best practices: the board](../docs/best-practices/board.md). |
| `area.mjs` | Area templates. `node tools/area.mjs <map-dir> --shape burst\|cone\|line\|emanation --ft N [--caster ID\|NAME\|X,Y[,SIZE]] [--at X,Y] [--dir NAME] [--angle DEG] [--toward X,Y] [--state FILE] [--by gm\|player] [--no-walls]`. `--height FEET` puts a burst's point in the air (cones, lines and emanations start at the caster's elevation). Prints the squares covered and reached past walls, who is in the area and who is out of its reach above or below (tokens from `--state`), and the `templates/<id>` record to write to the board. |
| `effect.mjs` | Effect badges. `node tools/effect.mjs <token.json> (add <condition> [VALUE] \| custom "<name>" [--kind good\|bad\|neutral] \| apply <effect-key> [--level N] [--pack DIR] \| remove <id or name> \| clear \| dead \| alive \| elevation <FEET>) [--detail T] [--until T] [--source T] [--gm-only]`; `node tools/effect.mjs list` shows the system's conditions. Reads a token record, checks against the system's conditions, prints the changed token to write back. Effects take `--duration "1 round" --expiry turn-end` (and `--records` or `--clock`, `--turn-of` for when they start). `apply` puts an effect from the content on the token (Heroism at rank 6: `apply spell-effects:effect/spell-effect-heroism --level 6`), its rules changing the creature's numbers; it also prints the content record for the board. |
| `fx.mjs` | Visual effects from chat. `node tools/fx.mjs play <effect> --map MAP [--state FILE] [--from ID\|NAME\|X,Y] [--to ID\|ID,ID\|targets\|X,Y\|template:ID] [--result hit\|crit\|miss] [--results ID=R,...] [--text T] [--texts ID=T,...] [--n N] [--colour #hex] [--kind K] [--traits a,b] [--gm] [--pack DIR]` prints the `fx/<id>` record to write (an unknown name says what it falls back to); `list [--search T] [--group T] [--pack DIR]` shows the library; `check <pack-dir>` checks a pack's `effects.json`. |
| `token.mjs` | Tokens from chat. `node tools/token.mjs add --state FILE --name "Wet-Nosed Rat" --type rat --at X,Y [--group G] [--alias A] [--kind foe\|npc\|pc] [--size S] [--speed FT] [--elevation FT] [--short L]` prints a new `tokens/<id>` record (a generated id; the letter picked free in its group; duplicate names warned about); `reveal --state FILE <name>` (the party learns a named NPC's name: `known: true`); `find --state FILE <name>`; `check --state FILE` (names and letters). |
| `ids.mjs` | Converts old ids to generated ones (`tok-`, `note-`, `tpl-` and 8 base-36 characters) with every reference: `convert <save-dir> [--ids MAPPING.json] [--dry-run]` (a save, in place, backup kept; one id per creature across the maps) and `records <records.json>` (the board's records: prints the `db_write` operations). |
| `actor.mjs` | Creatures' game data from chat. `node tools/actor.mjs <pack> <save> [--records FILE] list \| show <who> [--all] \| damage <who> <n> [type] [--crit] [--nonlethal] [--parts "5 fire, 3 slashing"] [--from DICE.json,...] \| heal <who> <n> \| temp <who> <n> \| recover <who> --roll N \| resource <who> <name> <+N\|-N\|N> \| shield <who> raise\|lower \| create <who> <content-key> [--name N] \| give <who> <content-key> \| option <who> <option> on\|off`. Numbers with breakdowns; prints the records to write (create and give include the content record when the board lacks it). `damage` also writes the damage card for the chat; `--from` gives the `dice.mjs` damage rolls it came from, shown on the card. |
| `clock.mjs` | The game clock and calendar: `node tools/clock.mjs <pack> <save> [--records FILE] show \| set "14 Gozran 4725 AR, 08:00" [--start] \| start \| advance "10 minutes" \| until 07:00`. Day 1 is the day the adventure began; advancing runs out effects whose time has passed. Prints `{lines, writes}` (`state/clock`, tokens). |
| `encounter.mjs` | Encounters from chat (the board has the same tracker): `node tools/encounter.mjs <pack> <save> [--records FILE] [--seed N] show \| start [<who>...] [--all] \| add <who> [--init N] \| init <who> N \| roll <who> [--roll D] [--stat S] [--mode higher\|lower] \| defeat <who> [--undo] \| hide <who> [--undo] \| begin \| next \| previous \| next-round \| previous-round \| delay \| resume <who> \| remove <who> \| end`. `roll` writes the roll card (a chat message, `chat/`) too; every command writes its audit lines, and (events go to the GM's audit log only, since 2026-11-12); `defeat` also gives the token its dead look on the map (hit points untouched) and `--undo` takes it away; `hide` hides the token itself from players; the board's tracker writes the same records. Turn changes run the ruleset's turn rules (persistent damage, frightened, fast healing, recovery checks, effects running out); a new round moves the clock. Prints `{lines, writes}` (`state/encounter`, `state/clock`, tokens, actorstate). `turns.mjs` holds what both share. |
| `chat.mjs` | Claude's messages in the board's chat, and audit lines: `node tools/chat.mjs narration "text" \| ruling "text" \| npc <who> "text" --pack P --save S [--records FILE] \| npc --as "Name" [--alias A] "text" \| audit "text" [--map M] [--warn]`, `--gm` for the GM's eyes only. Narration is the chat's heart; `audit` records a change Claude made in the GM's audit log (`event` is an audit line too: events are the GM's only since 2026-11-12). Check and damage cards come from `check.mjs` and `actor.mjs damage`. Prints the `chat/<id>` or `audit/<id>` record to write. |
| `library.mjs` | The content library: a content key (`creature/rat`, `pathfinder-monster-core:creature/goblin-warrior`) to its document, from the pack's own `content/` and the open sources `pack.json` lists, read only when asked for; which documents a campaign's creatures use (`referencedContent`, with the system's optional documents: a character's feat and feature descriptions) and `traitGlossary`. |
| `dice.mjs` | Claude's dice, logged for the board's Dice tab: `node tools/dice.mjs roll <formula> --who NAME [--kind K] [--gm] [--seed N] [--crit] [--type T] [--label L]` rolls and logs (`--crit` doubles a damage roll); `log --who NAME [--kind K] d20=14 2d6=3,5` logs dice rolled elsewhere. `--pack P --save S` finds the roller's token (public name, side), else `--side party\|others`. Prints `{lines, total, writes}` (the `dice/<id>` record). Log every roll. |
| `ledger.mjs` | The campaign ledger, the GM's memory (GM guide rule B5): `node tools/ledger.mjs add <kind> "text" [--title T] [--subjects "a, b"] [--area KEY] [--map M] [--source adventure\|added] [--added-by user\|claude] [--character PC] [--player NAME] [--by gm] [--link chat/<id>]... [--game LABEL] \| summary "text" [--title "Session N"] \| edit <id> [--text T] [--title T] [--subjects S] [--area A] [--source S] [--link L] \| close <id> [--failed] \| reopen <id> \| remove <id> \| find ["words"] [--kind K\|open] [--subject S] [--area A] [--by gm] [--chat] [--limit N] \| story \| subjects`, with `--records FILE` (the board's `ledger/` records, and `state/clock` and `board/meta` for the game time; `chat/` for `--chat`). Kinds: summary, thread, quest, event, improv, fact, secret, ruling. Writes print `{lines, writes}`; reads print lines. |
| `sound.mjs` | Sound (board/sound.js): `node tools/sound.mjs <pack> <save> [--records FILE] [--sounds DIR] status \| mood <auto\|explore\|combat\|boss\|town\|tension\|rest\|silence> \| boss <auto\|on\|off> \| next \| theme <map\|here> <mood\|none> \| cue <sting\|cue> [--gm] \| sounds [fx\|cues\|ambient\|music\|stings] \| ambient list\|add <loop> <x> <y> [--radius FT] [--inner FT] [--when always\|day\|night] [--volume V] [--label L] [--gm-only]\|set <id> [...] [--on\|--off]\|remove <id>`. Changes print `{lines, writes}`. The sound set's generator is `tools/sound/` (Python; `render.py`). Guide: [sound.md](../docs/best-practices/sound.md). |
| `exploration.mjs` | Exploration (board/explore.js; rules from the system's `exploration`): `node tools/exploration.mjs <pack> <save> [--records FILE] list \| activities \| set <PC> <activity\|none> [--expert PC] [--skill S] [--spell S] [--effect E] [--note N] \| pace \| travel <n> ft\|mi\|min\|hr [--terrain normal\|difficult\|greater] \| reminders \| requests \| content`. `travel` moves the clock at the party's pace (through `clock.mjs advance`); `tools/encounter.mjs roll` and `begin` apply the activities' combat requests. Changes print `{lines, writes}`. |
| `events.mjs` | Adventure events (engine/events/events.js; [events.md](../docs/best-practices/events.md)): `node tools/events.mjs <pack> <save> [--records FILE] status [id] \| due \| tick \| run <id> [stage] \| next <id> \| go <id> <stage> \| finish <id> \| reset <id> \| decide <id> <point> <choice> \| flag <name> [value] \| unflag <name> \| context`. `tick` does everything due and prints each stage's actions as Claude's checklist (flags and ledger entries written). `encounter.mjs end` sets `ended:<group>` flags. Changes print `{lines, writes}`. |
| `subsystem.mjs` | Subsystems (engine/events/subsystem.js; the system's kinds in `rulesets/<system>/subsystems.js`; [events.md](../docs/best-practices/events.md) 2c): `node tools/subsystem.mjs <pack> <save> [--records FILE] list \| show <id> [--player] \| start <id> [--show] \| check <id> <part> --who PC --skill S --roll N [--n K] [--bonus N] \| score <id> [part] <degree> [--who PC] \| add <id> <track\|part> <n> [--why W] \| round <id> \| reveal <id> <part\|track> [part\|check:N\|note:N\|threshold:ID] \| players <id> on\|off \| end <id> success\|failure\|done`. Thresholds set flags events wait on. Changes print `{lines, writes}`. |
| `players.mjs` | The campaign's players, who plays which PCs (`state/table.players`, saved in `campaign.json`; the ledger records which player and which character introduced a detail): `node tools/players.mjs list \| add "Chad" [--pcs "Kerra, Lyra"] [--gm] \| set "Chad" [--name N] [--pcs ...] [--gm\|--no-gm] \| remove "Chad" --records FILE`. Prints a merge of `state/table` to write. |
| `loot.mjs` | Party loot (board/loot.js; rules from the system's `loot`): `node tools/loot.mjs <pack> <save> [--records FILE] list [--view player] \| find "words" \| add item/<slug>\|"Custom name" [--qty N] [--to PC] [--from "the bugbear"] [--area KEY] [--value "25 gp"] [--bulk L\|1] [--text T] [--unidentified] [--mystery NAME] \| identify <item> [--as "False name"] \| unidentify \| appraise \| take <item> <PC> [--carry C] \| putback <PC> <item> \| give <PC> <item> <PC2> \| carry <PC> <item> held\|worn\|stowed \| invest <PC> <item> on\|off \| remove <item> \| sell <item> [--pc PC] [--price P] [--to PC] \| buy item/<slug> [--from PC] [--to PC] \| coins add\|take\|move "5 gp" [--pc\|--from\|--to] \| split [--between "A, B"]` (`--qty` for stacks). Changes print `{lines, writes}`: the content record a new library item needs, audit lines, and the encumbered condition on or off a token. |
| `think.mjs` | The "Claude is thinking" banner on its own, for any adjudication that is not a replay: `node tools/think.mjs start [--what T]` (`--what` for the GM's audit log only), `ping`, `stop`. A replay begun while it is up carries on with it. Prints `{lines, writes}`. |
| `replay.mjs` | Replays: resolve a batch of actions in a draft and let the table reveal it step by step on the board. `node tools/replay.mjs begin --records FILE --title T [--kind combat\|exploration\|social] [--map M]` (a working copy of the board's records; replays not yet revealed applied first; the "Claude is adjudicating" banner on), `records` (the working copy's file: give it to the other tools as `--records`), `get <path>`, `step --side pc\|npc\|env --text T [--actor WHO] [--gm] [--in FILE \| --in PATH=FILE ...] [--move TOKEN:X,Y[:VX,VY;...]]` (the other tools' outputs become the step's changes and posts, and their `roll`s its roll details), `narrate "text" [--focus WHO,WHO] [--gm] [--after N]` (a narration step right after the actions it tells, revealed with its own Next; end with one; `--after N` places it after step N), `stop "text"` (wait for reactions), `ping` (keep the banner up), `show` (each narration with the step it follows: check the order before `end`), `end` (the `replay/<id>` record), `abort`. Prints `{lines, writes}`; write the writes (each step's refreshes the banner). Procedure: [best practices: game data](../docs/best-practices/game-data.md) section 2c. |
| `headless/` | Headless checks of the board in Chrome: `smoke.mjs` walks the main features in both views (`NODE_PATH=$(npm root -g) node tools/headless/smoke.mjs`; run before publishing); `soundcheck.mjs` checks the board's sound with the real files over http (`--sounds DIR`); `board.mjs` holds the helpers (build a test board, open it, switch views, find tokens on screen, read and write records). |
| `check.mjs` | A check or Strike against a DC or a target's defence, with the degree of success, the creature's degree changes, rolling twice (`--roll 12,7`) and one-roll effects on the target. `node tools/check.mjs --mod 7 --dc 15 --roll 12`, or `<pack> <save> --who NAME (--stat S \| --strike W [--attack 2]) (--dc N \| --against NAME [--defense D]) --roll N [--bonus N]`. Its `writes` hold the d20s given, for the Dice tab: write them. `--bonus "1 backswing"` names a situational modifier; `roll` is the roll in parts (a replay step's details); its `writes` include the check card for the chat. |
| `import/foundry-pf2e.mjs` | Imports Foundry PF2E data in our format: every kind (creatures, hazards, vehicles, items, feats, actions, effects, conditions, spells, ancestries, heritages, backgrounds, classes, deities, campaign features; converters in `import/foundry/convert.mjs`). `node tools/import/foundry-pf2e.mjs --release <foundry-checkout> [--sources a,b] [--dry-run]` imports a whole Foundry release into the open content (`content/pf2e/`, ORC and OGL only), tracked by `import-manifest.json` (`import/foundry/track.mjs`): the report says what is new, changed by Foundry, changed on our side, renamed and retired, and applies our corrections (`content/pf2e/overrides/`). `<files> --out packs/<id>` writes a private pack (refuses folders in the repository other than `packs/`). |
| `note.mjs` | Map notes from chat. `node tools/note.mjs <map-dir> --at X,Y --text "TEXT" [--gm-only] [--by claude\|gm\|player] [--id note-XXXXXXXX]`. Gives the note a generated id (or the one given, to update it); checks the point is on the map and the text fits (500 characters); prints the `notes/<id>` record to write to the board. |
| `move.mjs` | Asks the movement engine. `node tools/move.mjs <map-dir> --token X,Y[,SIZE] (--to X,Y \| --step DX,DY \| --reach FEET) [--state FILE] [--diagonal 1,2] [--squeeze SIZE]`. Prints the cheapest path and its cost, whether one step is allowed, or every reachable position. |
| `fog.mjs` | Runs the fog of war for a map state: what the PCs see now, which tokens players may see, and the merged explored area. `node tools/fog.mjs <map-dir> --state FILE [--token ID:KIND:X,Y[,SIZE] ...] [--out FILE] [--range FEET]` (range unlimited by default). With `--out`, writes the updated map state (a `--token` with an id not in the state is a scratch token, not written). |
| `wall_overlay.py` | Draws a map's wall segments for review, colour-coded by type with one-way arrows. `python3 tools/wall_overlay.py <map-dir> [--out file] [--blank] [--sight X,Y ...] [--state FILE]`. `--blank` draws on a plain grid instead of the map image; `--sight` shades what is visible from each point and `--token X,Y,SIZE` what a token sees, both through `sight.mjs`. `--path X,Y,SIZE:GX,GY` draws a route and `--reach X,Y,SIZE:FEET` shades reachable positions, through `move.mjs`. `--fog player\|gm` paints the fog of war for a state's tokens, through `fog.mjs`. |
